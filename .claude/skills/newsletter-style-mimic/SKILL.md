# ニュースレター文体模倣スキル

ライフプランアドバイザー協会のニュースレター（Wordファイル）の文体・トーン・言い回しを参照し、同じスタイルで記事本文を執筆・書き直しする。

## 参照するWordファイルのパス

ニュースレターのルートディレクトリは以下。配下は `年/年_月/ワード原稿/校正後データ/` の構造で、各月に `お客様向けニュースレター.docx` と `巻頭.docx` がある（校正後が最終版）。

```
/Users/okazakimitsuruakira/Library/CloudStorage/GoogleDrive-okazaki@helplife.jp/共有ドライブ/ライフプランアドバイザー協会/ニュースレター関連/ニュースレター/
```

- 年フォルダは `2016`〜`2026` が存在（2025・2026は各12ヶ月分。古い年ほど一部欠けや構造差あり）。
- 月フォルダ命名は `2026_06` / `2025_12` 形式。ファイル名は `26_06 お客様向けニュースレター.docx` のように `年下2桁_月` 接頭辞付き（スペース有無・「のコピー」付きなど表記揺れあり）。
- `.gdoc`（Googleドキュメント形式）は textutil で開けないのでスキップし、次に新しい月を使う。

**参照方針（新しい月から遡る）：**
- 最低限、直近2〜3号の `お客様向けニュースレター.docx` を読んで文体を確認する。
- **より深い分析を求められた場合**は、2025年フォルダまで遡って複数号（目安6〜12本）を読み、文末・言い回しの頻出パターンや「鉄板ネタ」の再現性を確認する。
- 経営者・工務店向けの記事を書く場合のみ `巻頭.docx` を参照（後述のトーン差に注意）。

**遡り順（例）：**
1. `2026/2026_06/ワード原稿/校正後データ/`（最新）
2. `2026/2026_05/...` → … → `2026/2026_01/...`
3. `2025/2025_12/...` → `2025/2025_11/...` → … → `2025/2025_01/...`

校正後データが見つからない月は `作業後データ` や `ワード原稿` 直下も確認してよい。読み込みは `textutil -convert txt -stdout "[ファイルパス]"` をBashで実行する。複数ファイルは1コマンドで連続出力すると効率的。

## 分析済み文体の特徴

以下は実際のニュースレターから抽出した文体の特徴。Wordファイルを読み込んだ場合は、これに追加・更新して使用すること。

### トーン・スタンス
- **親しみやすい専門家**：金融・ライフプランの専門知識を持ちながら、お客様に寄り添う語り口
- **一人称は「私」**：書き手が顔を出し、体験・意見を率直に述べる
- **読者への語りかけ**：「〜ですよね」「〜ではないでしょうか」「〜してみてください」

### 文章構造の特徴
- **導入は読者の悩み・疑問から始まる**：「こんな不安をよく耳にします」「〜と思っている人が意外と多い」
- **問いかけ → 解説 → 結論**の流れ
- **具体的な数字を多用**：「5,000万円」「月々5万円」「35年後」など
- **短文と長文のリズム**：短い断言文のあとに、長い説明文が続くパターン

### 文末表現のパターン
```
断言型：「〇〇なのです。」「〇〇ということです。」
驚き型：「なんと〇〇になっています。」「そうなると〇〇円も〇〇することになります。」
共感型：「〜ですよね。」「〜ではないでしょうか。」
警告型：「〜ということが一番危険です。」「〜することはできないからです。」
推奨型：「〜をお勧めします。」「〜ことが重要ですね。」
```

### 特徴的な言い回し
- 「〜ということを知らない人が意外と多い」
- 「〜なのにも関わらずです」（強調の倒置）
- 「書いてしまえば簡単ですが」（難しさへの共感）
- 「あくまでも〜でしかありません」（誠実な留保表現）
- 「実は〜」（意外性の提示）
- 「正直言って〜」（本音の吐露）
- 「では、〇〇とは何か？」（自問自答形式）
- 「そこで今回は〜」（テーマ提示の接続詞）
- 「〜というのは〜ということ」（定義の言い換え）

### 構成テンプレート
```
1. 読者の悩み・状況の提示（共感）
2. 「実は〜」「ここで〜」で問題の核心を提示
3. 具体的な数字・事例で説明
4. 「では、どうすれば？」と問いかけて解決策へ
5. 結論・推奨アクションを明示
6. 「〜することが重要ですね」で締める
```

### 追加分析（2026年1〜6月号・お客様向け6本＋巻頭を精読して抽出）

**タイトルの型**
- カギ括弧＋疑問・煽りの「！？」「？」を多用。例：「住宅ローンを50年返済で、老後にお金が貯まる！？」「資金計画を行う正しい順番！？」「市場が予測する『10年後の変動金利』」
- 直近の制度改正・利上げ・統計など「旬のニュース」を切り口にする

**冒頭の型（3パターン）**
- ①お客様の生の声をカギ括弧で：「『家が欲しい。でも住宅ローンを払いながら老後費用が残せるのか？』こんな不安をよく耳にします」
- ②世間の通説・営業トークを置いて反証：「『〜ですよ』そう言うハウスメーカーの営業マンも多いかもしれません。しかし〜」
- ③断定で問題提起：「〜ということを知らない人が意外と多い」

**数字の見せ方**
- 「フラット50で月10.5万円、35年より2.5万円安い」のように、必ず差額・比較・倍率で語る（例：「0.5％→2.5％は4倍以上」「月5万円アップ」）
- 専門用語は出したら必ずかみ砕く＋留保（例：「インプライド・フォワードレートという計算方法」「あくまでも一つの仮説でしかありません」）
- 「なんと〜になっています」で驚きを演出

**論の運び方（お客様向けの定番ロジック）**
- 「金利の安い変動で借りて、上がったら固定に借換すればいい、という甘い考えが一番危険」＝代表的な警告フレーズ（複数号で繰り返し登場する“鉄板ネタ”）
- 「問題はローンの選び方ではなく、ローンとの付き合い方」のように、論点をずらして本質に誘導
- 余裕資金はNISA等で運用へ＝協会の一貫した推奨着地点
- ハウスメーカー/工務店を「出口戦略まで提案できる会社こそ信用できる」と評価軸を提示して締めることがある

**中盤・結論の見出し**
- 「結論：対策はどうする？」「では、正しい順番とは何か？」と問いを見出しにする
- 手順は「第1に〜／第2に〜」または「①②③」で列挙

**巻頭（経営者向け）のトーン差 ※お客様向けとは別人格**
- 一人称が「岡崎的には〜」になる（社長個人の見解として踏み込む）
- 「結論から言うと」「釈迦に説法ですが」「言い方を換えれば」「逆に言えば」が多い
- 図表・出典を明記し、PL対CFのような対比概念で整理する
- ※お客様向け記事を書くときは巻頭トーンを混ぜない（読者層が違う）。経営計画・工務店向けのときのみ巻頭トーンを使う

**誠実さの担保（協会らしさの核）**
- 必ずリスク・前提条件を添える：「あくまで理論的にはそうなるのですが、運用にはリスクがあるのも事実です」「全てが順調にいくことばかりではない」
- 数字は「試算」「イメージ」と断り、断定しすぎない

## 実行手順

### Step1：Wordファイルを読み込む

Bashで以下を実行し、`お客様向けニュースレター.docx` を取得する：

```bash
textutil -convert txt -stdout "[ファイルパス]"
```

- **通常**：最新月から順に直近2〜3号を読む。
- **「もっと深く分析」「文体を深化」等を求められた場合**：2025年フォルダまで遡って6〜12本を読み、頻出する文末・言い回し・構成・鉄板ネタ（例：「金利が上がったら借換すればいい、は一番危険」）の再現性を確認する。新しく見つけた特徴は、上の「分析済み文体の特徴」セクションに追記して恒久化する。

### Step2：文体特徴の最新情報を抽出

読み込んだテキストから以下を抽出・確認する：
- 冒頭の導入パターン（何で始まるか）
- よく使われる接続詞・文末表現
- 数字・具体例の使い方
- 特徴的な言い回し

### Step3：指定された内容を同じ文体で執筆・書き直す

ユーザーから渡された内容（テーマ or 元の文章）を、抽出した文体で書き直す。

**書き直しの際のチェックリスト：**
- [ ] 導入は読者の悩みや状況から入っているか
- [ ] 「実は」「そこで」「では」などの特徴的な接続詞を使っているか
- [ ] 具体的な数字・金額・期間が入っているか
- [ ] 短文と長文が混在したリズムになっているか
- [ ] 「〜ですよね」「〜なのです」などの文末表現が使われているか
- [ ] 最後に推奨アクションか前向きな締めの一文があるか
