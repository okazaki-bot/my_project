# マーケティングWeb制作スキル（LP／サイト）

## このスキルの前提

- **主な案件**: クライアント案件（工務店・不動産などの地域BtoC商材）
- **対象**: LP（1枚完結）とコーポレートサイトの両方。冒頭で **LPモード / サイトモード** を判別して分岐する
- **成果物**: ①設計書（構成案＋コピー）②HTML/CSS一式（素のHTML＋CSS。必要ならWP貼り付け版を派生）
- **スキルの範囲外**: 広告規制チェック（景表法・不動産公正競争規約）、GA4等の計測実装、A/Bテスト設計。**これらは扱わない**。ただし明らかに危ない表現（「絶対」「完全」「日本一」など）を書きそうになったら、自分では使わず代替表現にする
- **やらないこと**: ヒアリング前に成果物を書き始める／固定テンプレートに流し込む／抽象語で埋める

## 絶対に守る原則

1. **ヒアリングを飛ばさない。** 必須7問（下記）を提示し、回答を得てから設計に入る
2. **構成はテンプレートではなく訴求から導く。** 「PASONAだからこの順」ではなく「この読者がこの順に疑問を持つからこの順」。導出の手順は `references/structure-principles.md`
3. **抽象語を成果物に残さない。** 「安心」「高品質」「豊富な実績」「お客様第一」は、それ単体では情報量ゼロ。必ず具体に置き換える（`references/copywriting.md`）
4. **数字・実績・お客様の声は捏造しない。** 素材がない箇所は `【要確認：施工実績の件数】` の形で明示し、推奨素材リストに載せる
5. **段階ごとに成果物を出して止まる。** 設計書を出したら承認を待つ。承認前に実装へ進まない

## ワークフロー

### STEP 0 — モード判別

依頼内容から次を確認（不明なら1問だけ聞く）。

- **LPモード**: 1つのCVに向けた1枚完結ページ（申込・予約・資料請求・相談）
- **サイトモード**: トップ＋下層ページの構造を持つコーポレート／集客サイト

サイトモードの場合も、ヒアリングと訴求設計は共通。構成フェーズで「サイト全体の情報設計 → 各ページの役割 → トップの構成」の順に降りる。

### STEP 1 — ヒアリング（必須7問／2段構え）

まず以下の**必須7問**をそのまま提示する。クライアントにそのまま転送できる文面で出すこと。

```
■ Web制作ヒアリング（必須）

Q1【商材】何を売る／何に申し込んでもらうページですか？
　　価格帯・提供エリア・提供までの流れも書けるだけ書いてください。

Q2【CV（ゴール）】このページで来訪者に取ってほしい行動は何ですか？
　　例：来場予約 / 資料請求 / 無料相談申込 / 電話 / LINE登録 / 見積依頼
　　※複数ある場合は「最優先の1つ」を決めてください。

Q3【ターゲット】いちばん来てほしいお客様はどんな人ですか？
　　年代・家族構成・住まいの状況・年収帯・いま何に困っているか。
　　「こういう人は来なくていい」も書いていただけると助かります。

Q4【流入経路】お客様はどこからこのページに来ますか？
　　例：Google検索（検索語も）/ Instagram広告 / チラシのQR / 紹介 / 名刺

Q5【強み】競合ではなく御社が選ばれている理由は何ですか？
　　過去に成約したお客様が「決め手」として口にした言葉があれば、そのまま。

Q6【競合】比較検討されている会社・サービスを2〜3件（社名 or サイトURL）。
　　「そこには負けている点」も正直に書いてください。

Q7【素材】いま手元にあるものにチェック：
　　□ ロゴ　□ 施工写真／商品写真　□ スタッフ写真　□ お客様の声
　　□ 実績数値（施工件数・満足度など）　□ 会社案内・既存パンフ
　　□ 既存サイト（URL）　□ 資格・受賞・加盟団体
```

**トーンの確認（必ずここで決める）**
コピーのトーンは案件ごとに選ぶ。次の3択で確認する。

| トーン | 向く商材 | 特徴 |
|---|---|---|
| A. 誠実・信頼重視 | 住宅・不動産・士業などの高額／長期検討商材 | 誇張を避け、事実・数字・第三者の声で積み上げる |
| B. レスポンス広告系 | 期限のあるイベント・セミナー・キャンペーン | 強いキャッチ・限定性・緊急性を使う |
| C. 中間（親しみ＋誠実） | 地域密着・BtoC全般 | 話し言葉寄りで距離を詰めつつ、根拠は示す |

回答が返ってきたら、**訴求の弱い箇所だけ**深掘り質問を追加する。深掘り質問の一覧は `references/hearing-sheet.md` を読む（Q3の答えが薄い＝ターゲット深掘り、Q5が「丁寧な対応」等の抽象語＝強み深掘り、など）。

回答が一部しか返らない場合は、埋まっていない項目を `【要確認】` として明示したまま先に進んでよい。ただしQ1・Q2・Q3のいずれかが空のまま設計に入ってはいけない。

### STEP 2 — 訴求設計（marketing-brief）

`references/appeal-design.md` を読み、以下を成果物として書く。ここが品質のすべてを決めるので、手を抜かない。

1. ペルソナ（1人に絞る。名前・状況・その人の1日）
2. 認知段階の判定（無自覚／問題自覚／解決策自覚／商品自覚／確信済み）と流入経路との整合
3. 読者の本音（インサイト）と、口にしない前提
4. 反論リスト（「でも…」を最低8個）
5. ベネフィット翻訳表（機能 → 効果 → その人にとっての意味）
6. ポジショニング（競合の主張を並べ、空いている席を特定）
7. 一言訴求（このページは誰に何を約束するのか、を1文で）
8. オファー設計（CVのハードル、リスクリバーサル）

出力先: `案件フォルダ/01-marketing-brief.md`

**ここで一度止めて、一言訴求とポジショニングの妥当性を確認する。**

### STEP 3 — 構成設計

`references/structure-principles.md` を読み、訴求から構成を導出する。テンプレートを当てない。

手順の骨子：
1. ファーストビューで言い切る一文を決める（認知段階から逆算）
2. 読者の心の質問を「浮かぶ順」に並べる ＝ これが構成
3. 各質問に1セクション＝1メッセージを割り当てる
4. 反論が発生するタイミングに、その反論処理を差し込む
5. 確信のピークにCTAを置く

出力先: `案件フォルダ/02-structure.md`（セクション番号／役割／読者の心の状態／入れる要素／必要素材）

### STEP 4 — コピー執筆

`references/copywriting.md` を読み、STEP 1で決めたトーンで書く。見出し・本文・ボタン文言・マイクロコピーまで、実際に載る文字をすべて書く。

出力先: `案件フォルダ/03-copy.md`

STEP 3・4をまとめて **設計書** として提示し、**承認を待つ**。

### STEP 5 — 実装（HTML/CSS）

`references/implementation.md` を読む。素のHTML＋CSSを標準とする。

- 写真・ロゴが未提供の箇所は **プレースホルダ**（アスペクト比を維持したインラインSVG／CSS）で組む
- 同時に **推奨素材リスト** を出力する（どの位置に、どんな写真が、何枚必要か。撮影時の注意まで）
- モバイルファースト。実機幅375pxで崩れないことを最優先

出力先: `案件フォルダ/index.html`, `案件フォルダ/style.css`, `案件フォルダ/04-required-assets.md`

WordPressに貼る必要が出たら、この後に派生版を作る（手順は `references/implementation.md`）。

### STEP 6 — チェックリスト提示

`references/checklist.md` の内容を、その案件に合わせて具体化して提示する。**自分で採点や修正はしない。** 判断はユーザーに委ねる。

## 出力先の規約

プロジェクト直下に案件別フォルダを作る。

```
~/Documents/my_project/lp-<案件名>/        ← LPモード
~/Documents/my_project/site-<案件名>/      ← サイトモード
├── 00-hearing.md              ヒアリング質問紙と回答
├── 01-marketing-brief.md      訴求設計
├── 02-structure.md            構成設計
├── 03-copy.md                 コピー全文
├── 04-required-assets.md      推奨素材リスト
├── index.html
├── style.css
└── assets/                    画像等
```

既存リポジトリに入れるべき案件かどうか迷ったら、フォルダを作る前に1問だけ確認する。

## 既存ページの改善依頼の場合

STEP 0の前に現状ページを読み（WebFetchまたはローカルファイル）、`references/structure-principles.md` と `references/copywriting.md` の観点で **現状の問題点を先に言語化**してから、STEP 1のヒアリングに入る。ヒアリングは「なぜこの表現にしたのか」「実際の反響はどうか」を必須7問に追加して聞く。
