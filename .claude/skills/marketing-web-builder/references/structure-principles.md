# 構成設計の原則（テンプレートを当てない）

このスキルは「LPの黄金構成」を持たない。理由は単純で、**構成は読者の疑問の順序で決まる**からであり、
読者が変われば順序も変わる。テンプレートに流し込むと、必ずどこかに「その読者が今聞きたくない話」が挟まる。

---

## 構成を導出する5ステップ

### STEP A — ファーストビューで言い切る一文を決める

`01-marketing-brief.md` の **認知段階** と **一言訴求** から逆算する。

ファーストビューは3秒で3つの判定を通過しなければならない。

1. **これは何のページか**（What）
2. **自分向けか**（Who）
3. **次に何をすればいいか**（Next）

この3つが揃っていれば、デザインが地味でも離脱しない。逆に、美しいが「誰向けか分からない」ファーストビューは必ず落ちる。

構成要素は最小で4つ：
- キャッチコピー（＝一言訴求を読者の言葉に翻訳したもの）
- サブコピー（キャッチで言い切れなかった条件・根拠を1〜2行）
- 対象の明示（「◯◯でお悩みの方へ」／「対応エリア：◯◯市・◯◯町」）
- ファーストビュー内のCTA（＋電話番号。BtoC地域商材では電話が主要CVになることが多い）

**認知段階ごとの第一声の違い**（これが構成が固定できない理由）：

| 認知段階 | ファーストビューの入り方 | やってはいけない入り方 |
|---|---|---|
| ①無自覚 | 事実・数字で問題を可視化（「築30年の家、冬の朝の室温は平均◯℃」） | 商品名・会社名から始める |
| ②問題自覚 | 悩みの言語化＋「解決できる」の提示 | 悩みの共感を長々やる（もう分かっている） |
| ③解決策自覚 | 「その方法の中で、なぜこの選択か」 | 問題提起から始める（冗長で離脱） |
| ④商品自覚 | 差別化と比較の答え | 一般的な悩みの話 |
| ⑤確信済み | オファー・条件・申込導線を最上部に | 説明を読ませようとする |

### STEP B — 読者の心の質問を「浮かぶ順」に並べる

これが構成そのものになる。ペルソナがファーストビューを読み終えた直後から、
**時間軸に沿って**頭に浮かぶ質問を書き出す。

例（③解決策自覚・中古リノベを検討中の30代夫婦）：

1. これは自分のエリア・予算の話か？
2. 中古＋リノベって、実際いくらかかるの？
3. どんな家になるの？（見せて）
4. でも古い家って、耐震とか大丈夫なの？
5. この会社は何をしてくれる会社？（仲介？工事？両方？）
6. なんでこの会社に頼むといいの？他社と何が違う？
7. 本当にできてる？（他の人の実例と声）
8. 相談したら何をされる？営業される？
9. いくらかかる？いつまでに決めないといけない？
10. で、どうすればいい？

**この10個の並びが、そのまま10セクションの並びになる。**
「共感 → 問題提起 → 解決策 → 実績 → 声 → CTA」のような抽象的な型を経由する必要はない。

質問を並べるときの原則：
- **読者が先に知りたいことを先に置く。** 会社の想い・沿革は、ほぼ常に後半
- **「自分向けか」の確認は最速で終わらせる。** エリア・価格帯・条件は上から3スクロール以内
- **重いもの（価格）を隠さない。** 隠すと「聞かないと分からない会社」になり離脱する。幅でも範囲でもいいので出す
- **1セクション＝1メッセージ。** 2つ言いたくなったら2セクションに割る

### STEP C — 各セクションに「役割」と「読者の心の状態」を書く

構成表は次の5列で書く。

| # | セクション | 答える質問（読者の心の声） | 入れる要素 | 必要素材 |
|---|---|---|---|---|
| 1 | ファーストビュー | これは何のページ？自分向け？ | キャッチ／サブ／対象明示／CTA／電話 | 主要写真1点・ロゴ |
| 2 | 対象と提供範囲 | 自分のエリア・予算の話か？ | 対応エリア地図・価格帯の幅 | 【要確認：価格帯】 |
| 3 | 総額の内訳 | 実際いくら？ | 内訳の実例3パターン（表） | 【要確認：事例3件の総額】 |
| … | | | | |

「入れる要素」の欄が **文章だけ** になっているセクションが3つ以上続いたら、そこは読み飛ばされる。
表・写真・図・箇条書き・お客様の声のいずれかを挟む。

### STEP D — 反論処理を「発生する場所」に差し込む

`01-marketing-brief.md` の反論リストを、**その不安が生まれる直後**のセクションに配置する。
末尾のFAQに全部まとめるのは最悪の設計で、不安を抱えたまま読み進める時間が長くなる。

- 価格を見せた直後 → 「予算が超えたらどうなるのか」への答え
- CTAの直前 → 「営業されるのでは」「まだ何も決まっていないのに」への答え
- 実績を見せた直後 → 「自分の条件だと当てはまらないのでは」への答え

FAQセクションに残すのは、**読者の意思決定を左右しない細かい確認事項**（駐車場の有無、営業時間、対応可能日など）だけ。

### STEP E — CTAは「確信のピーク」に置く

「LPには3回CTAを入れる」というような回数のルールは持たない。置く場所は次の3種類。

1. **ファーストビュー内**（⑤確信済みの読者と、指名検索で来た人を待たせない）
2. **確信が跳ね上がった直後**（価格の内訳を見せた後、実例を見せた後、お客様の声の後）
3. **最後**（読み切った人のために、必ず）

加えて、スマホでは**固定フッターCTA**を1つ置く。ただし本文を隠さない高さに抑える。

CTAの直前には必ず、次の3つを添える。
- ハードルの低さ（「入力1分」「まだ検討段階の方が7割です」）
- リスクリバーサル（「当日の契約はお願いしません」）
- 次に何が起きるかの明示（「お送りいただくと、担当の◯◯より1営業日以内にご連絡します」）

## 離脱の4大要因（各セクションで自問する）

| 離脱理由 | 読者の心の声 | 対処 |
|---|---|---|
| 自分向けだと分からない | 「これ、うちの話じゃないな」 | 対象・エリア・条件を上部で明示。ペルソナの状況をそのまま書く |
| 信じられない | 「どこも同じこと言ってるし」 | 主張の直後に証拠（数字・写真・第三者の声・具体名）をセットで置く |
| 面倒そう | 「あとで見よう」 | 入力項目削減、所要時間明示、段階的CTA |
| 今じゃなくていい | 「急ぎじゃないし」 | 実在する期限（開催日・棟数・制度期限）／先延ばしの実損を数字で |

**主張と証拠は必ず隣に置く。** 主張だけのセクションが1つあると、その後の主張も全部疑われる。

## スクロールの設計（LPモード）

- **読者は読まない。スキャンする。** 見出しだけを拾い読みして、意味が通るか確認する（`copywriting.md` の「見出しだけ通読テスト」）
- 1画面（スマホ約667px）に**1メッセージ**。1画面に2つの主張が入ると両方薄まる
- セクションの切り替わりは、背景色・余白で明確に区切る。境目が曖昧だと読者は「同じ話がまだ続いている」と感じて飛ばす
- **総スクロール長は目標CVのハードルに比例させる。** 電話1本なら短く、来場予約や高額商材なら長くてよい。「短いLPが良い」は誤り。必要な情報を削ると決まらない

## サイトモードの情報設計

サイトモードは「トップの構成」を考える前に、**サイト全体の役割分担**を決める。

### 1. ページ一覧と役割を決める

各ページに次を割り当てる。省略できるページは作らない（作ると更新されず、信頼を下げる）。

| ページ | 役割（読者のどの疑問に答えるか） | 主な流入 | ゴール |
|---|---|---|---|
| トップ | 何の会社か／自分向けか／どこへ進むか | 指名・SNS | 下層への振り分け |
| サービス／商品 | 何をしてくれるのか、いくらか | 検索 | 資料請求・相談 |
| 施工事例／実績 | 本当にできているのか | 検索・回遊 | 相談 |
| お客様の声 | 他の人はどう感じたか | 回遊 | 相談 |
| 会社案内・スタッフ | 信頼できる相手か | 回遊 | 相談 |
| よくある質問 | 細かい確認 | 回遊 | 相談 |
| お問い合わせ | 行動する場所 | 全ページ | CV |
| ブログ／お役立ち | 検索の入口（②問題自覚層の獲得） | 検索 | 回遊→相談 |

### 2. トップページは「振り分け」が主機能

トップで全部を説明しようとしない。トップの仕事は次の3つ。

- 3秒で「何の会社で、誰向けか」を伝える
- 訪問者のタイプ別に入口を用意する（「はじめての方」「土地をお持ちの方」「建替えをお考えの方」など）
- どのページからでもCVに戻れる導線を持つ

### 3. 回遊設計

- 各下層ページの末尾に「次に読むべき1ページ」を置く（関連リンクを羅列しない。1つに絞る方が動く）
- 事例 → 「この事例を担当したスタッフ」 → 「相談する」のように、**信頼が積み上がる順に繋ぐ**
- 全ページに同一のCTAブロックを共通コンポーネントとして置く

### 4. 検索流入ページ（ブログ）の扱い

②問題自覚層を拾うのが役割。記事ページのゴールは即CVではなく、
**「この会社は分かっている」と思わせてサービスページへ送ること**。記事末尾のCTAは相談ではなく資料請求など1段低いものにする。

## この段階の完了判定

- [ ] ファーストビューの一文が、認知段階と整合している
- [ ] セクションの並びが「読者の質問が浮かぶ順」になっている（型の順ではない）
- [ ] 反論処理が、その不安が生まれる場所に置かれている
- [ ] すべての主張の隣に証拠がある
- [ ] 各セクションに1メッセージだけが入っている
- [ ] CTAが確信のピークに置かれている
- [ ] 素材が足りない箇所が全部 `【要確認：…】` になっている
