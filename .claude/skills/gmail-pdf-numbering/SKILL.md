# Gmail PDF 番号付与・振り分けスキル（v3）

Gmailの指定ラベル内のPDF添付を取得し、ベースフォルダ直下に「第N回」フォルダを作って振り分ける。回数は既存の「第N回」を検出して自動採番する（第1回があれば次は第2回）。

フォルダ構成（既存「第1回」と同形式）:

```
ライティング講座（森田石材）/
├── 第1回/ …（既存）
└── 第2回/                      ← 今回自動作成（既存最大+1）
    ├── 提出/                   ← 元PDF。ファイル名「<送信者名>_<アラビア数字>.pdf」
    │   ├── 伊藤幸恵_1.pdf
    │   └── 山下将平_2.pdf …
    ├── 匿名化/                 ← 番号スタンプ済み。ファイル名「<丸数字>.pdf」名前なし＝匿名
    │   ├── ①.pdf
    │   └── ②.pdf …
    ├── 送付用/                 ← 空フォルダ（手動運用用）
    └── _report.json
```

- 番号は**ダウンロード総数 N から 1〜N をランダムに重複なく**割り当てる
- `提出` と `匿名化` で同じ番号を使う（提出はアラビア数字、匿名化は同じ数字の丸付き）
- 元PDFは必ず保持（作業フォルダの原本は上書きしない）

## 依存ライブラリ

```bash
pip install pypdf reportlab google-api-python-client google-auth-httplib2 google-auth-oauthlib
```

Gmail OAuth認証の初回セットアップについては → `scripts/download_attachments.py` のコメントを参照。

## 実行フロー

### Step 0: パラメータ確認

| パラメータ | 説明 | 例 / デフォルト |
|---|---|---|
| `LABEL_NAME` | Gmailラベル名（入れ子は full path） | `提携先企業/森田石材/ライティング宿題` |
| `FILTER_CONDITION` | 抽出条件 | `all` / `unread` / `days:30` / `month:2026-06` / `from:` / `subject:` / 生の `after:.. before:..` |
| `BASE_DIRECTORY` | 振り分け先ベースフォルダ（この直下に第N回を作成） | デフォルト: `/Users/okazakimitsuruakira/Library/CloudStorage/GoogleDrive-okazaki@helplife.jp/共有ドライブ/ライフプランアドバイザー協会/セミナー関連/ライティング講座/ライティング講座（森田石材）` |
| `KAI`（任意） | 回数を明示指定 | 省略時は既存「第N回」を検出して自動採番 |

注意点:
- ラベルが見つからない場合、スクリプトが利用可能なラベル一覧を出力する。入れ子ラベルは `親/子/孫` の完全パスで再指定すること。
- 同じ親フォルダに `ライティング講座（墓石店）` `ライティング講座（工務店）` もある。別講座と判断できる場合はベースフォルダを差し替える。

### Step 1: PDF添付のダウンロード（作業フォルダへ）

ダウンロードは一時作業フォルダに行う（Google Drive同期フォルダを汚さないため）。

```bash
STAGING="/tmp/gmail_pdf_$(date +%Y%m%d_%H%M%S)"
python scripts/download_attachments.py \
  --label "[LABEL_NAME]" \
  --filter "[FILTER_CONDITION]" \
  --output "$STAGING"
```

- 指定ラベルが存在しない → エラー報告（利用可能ラベル一覧つき）して処理中断
- 対象メール0件 / 添付PDF0件 → 報告して正常終了
- 各メールのFromヘッダーから**送信者名**を抽出して記録（MIMEエンコードは自動デコード、表示名がなければアドレスの@より前）
- 出力: `$STAGING/_manifest.json`

### Step 2: 第N回フォルダへの振り分け・番号挿入

```bash
python scripts/stamp_pdf.py batch \
  --manifest "$STAGING/_manifest.json" \
  --base-dir "[BASE_DIRECTORY]"
  # 回数を明示したい場合のみ: --kai 3
```

処理内容:

1. `BASE_DIRECTORY` 直下の `第N回` を検出し、最大+1 の回フォルダを作成（`--kai` 指定時はその番号）
2. `提出` `匿名化` `送付用` の3サブフォルダを作成
3. ダウンロード総数 N から `1〜N` をシャッフルして各PDFに重複なく割り当て
4. `提出/<送信者名>_<アラビア数字>.pdf` に元PDFをコピー（原本は保持）
5. `匿名化/<丸数字>.pdf` に番号スタンプ済みPDFを保存（名前なし）
6. 出力: `第N回/_report.json`

### Step 3: 処理後の後始末とレポート

1. 一時作業フォルダ（`$STAGING`）を削除する
2. `第N回/_report.json` を読み込み、以下の形式で報告する

## 番号挿入仕様

- 採番: ダウンロード総数 N に対し 1〜N のランダム順列（重複なし）
- 提出側ファイル名: アラビア数字（`<送信者名>_7.pdf`）
- 匿名化側ファイル名: 同じ数字の丸付き、名前なし（`⑦.pdf`）
- スタンプ位置: 1ページ目の右上（上端・右端から各 7mm 内側）
- スタンプサイズ: 直径 10mm（1cm × 1cm 以内）
- 描画方式: 白地の円 + 中央にアラビア数字（Helvetica-Bold）。丸数字は ① 〜 ㊿、51以上は `(51)` 形式
- 元ファイルは必ず保持する

## 送信者名の扱い

- Fromヘッダーの表示名を使用（MIMEエンコードは自動デコード）
- 表示名がない場合はメールアドレスの@より前を使用
- 組織名つき表示名（例:「もみじ市民ホール 門脇亮太」）はそのまま使用する
- フォルダ名・ファイル名に使えない文字（`\ / : * ? " < > |` 等）は自動除去

## 例外処理

| 状況 | 対応 |
|---|---|
| ラベルが存在しない | 処理中断・利用可能ラベル一覧つきでエラー報告 |
| 対象メール0件 | 正常終了・「対象なし」報告 |
| 添付PDF0件 | 正常終了・「対象PDFなし」報告 |
| 送信者名が特定できない | アドレスの@より前で代替・備考欄に記録 |
| 破損PDF | スキップ・ファイル名と理由を記録 |
| パスワード保護PDF | スキップ・ファイル名と理由を記録 |
| 保存先に書込権限なし | 処理中断・エラー報告 |
| 同名ファイル衝突 | タイムスタンプ付与で別名保存・記録 |
| 丸数字描画不具合 | 代替描画へ自動切替・備考欄に記録 |

## 禁止事項

- 指定外のラベルを参照しない
- PDF以外の添付ファイルを処理しない
- 元ファイルを上書きしない
- 同じ番号を複数ファイルに付与しない
- エラー・スキップを黙って無視しない

## 検収条件（処理完了の判定基準）

1. 指定ラベルの対象メールが正しく参照されている
2. PDF添付のみ抽出されている
3. ダウンロードPDF件数が報告件数と一致している
4. 番号がダウンロード総数 N の範囲（1〜N）で重複なく割り当てられている
5. ベースフォルダ直下に既存最大+1の「第N回」が作成されている
6. 第N回直下に `提出` `匿名化` `送付用` が作成されている
7. `提出` に `<送信者名>_<アラビア数字>.pdf` 形式の元PDFが保存されている
8. `匿名化` に `<丸数字>.pdf` 形式（名前なし）のスタンプ済みPDFが保存されている
9. 各匿名化PDFの1ページ目右上に番号が挿入されている（サイズ 1cm × 1cm 以内）
10. 元PDFが上書きされていない
11. ファイル対応表（番号割り当て一覧）が出力されている
12. スキップ・失敗案件が明示されている
