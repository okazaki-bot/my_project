# スライド・ドキュメント校正スキル

PowerPoint / Word / PDF を対象に、次の3点を点検し、指摘する。修正はユーザーの
指示を受けてから行う。

1. **誤字脱字** — 漢字変換ミス（同音異義語の誤変換）、タイプミス、抜け字、
   送り仮名の誤り、表記ゆれ。**特に漢字変換ミスは前後の文脈から判断する**（後述）
2. **不適切・不自然な表現** — 誤用、二重敬語、冗長、文体の不統一、読み手に
   失礼/不正確になりうる言い回し
3. **重複スライド/ページ** — スライドはページをコピーして作るため、「直して使う
   つもりでコピーした古いページの消し忘れ」「同じページの二重挿入」が起きやすい。
   これを洗い出す。

校正（1・2）は文章の意味を読んで判断する作業なので**モデル自身が読んで指摘**する。
抽出と重複検出と修正適用は**スクリプトに任せて確実に**行う。この分担が肝。

## 依存ライブラリ

```bash
pip install python-pptx python-docx pypdf
```

## 進め方

### Step 0: 対象ファイル/フォルダの確認
- **対象はユーザーに指定してもらう。** プロジェクト内を勝手に探して推測で進めない。
  パスが示されていなければ「どのファイル（またはフォルダ）を見ますか？」と必ず尋ねる。
  ドラッグ&ドロップやコピペのパス、`~/Desktop/...` などどんな形でも受け付ける。
- **ファイル指定**: そのファイルだけを対象にする。
- **フォルダ指定**: そのフォルダ直下（必要ならサブフォルダも、ユーザーに確認）の
  `.pptx` / `.docx` / `.pdf` を一覧化し、対象を確認してから1つずつ処理する。
  一覧が多いときは件数と内訳を見せ、全部やるか絞るかを尋ねる。
  ```bash
  # フォルダ内の対象ファイルを列挙（隠しファイル・バックアップは除外）
  find "<folder>" -maxdepth 1 -type f \( -iname '*.pptx' -o -iname '*.docx' -o -iname '*.pdf' \) \
    -not -iname '*.bak-*' | sort
  ```
- 拡張子が `.pptx` / `.docx` / `.pdf` 以外なら、対応していない旨を伝える。
- **PDFはチェック専用**。テキスト書き換えはPDFでは安全に行えないため、修正が
  必要なら元データ（pptx/docx等）で直す前提だと最初に伝えておく。
  （PDFでも「重複ページの削除」だけは可能。）
- 複数ファイルを処理するときは、ファイルごとにレポートを分けて提示する。

### Step 1: テキスト抽出（位置情報つき）
```bash
python3 scripts/extract.py <file>
```
スライド/ページ番号・ブロック種別（title/body/table/notes）つきで全テキストが
JSONで返る。これを読んで校正する。指摘では必ず**どこか（スライド3のタイトル、等）**
を添えること。後でユーザーが直す箇所を指定しやすくするため。

#### 校正の観点（一文ずつ「意味」で読む）
単語や行を孤立して見ると誤字は捕まらない。**必ず一文ずつ、その文が言いたいことを
掴んでから、表記が意味と合っているかを照合する**。機械的なスペルチェックでは
絶対に見つからない誤りを、文脈で拾うのがこのスキルの肝。次の3種類を特に意識する。

**(a) 漢字の変換ミス（同音異義語）** ― 最重要。単語単体では正しい漢字なので
文脈でしか判断できない。よくある取り違えの例（あくまで例。判断は文脈が全て）:
- 意志／意思／遺志、対象／対照／対称、保証／保障／補償、以外／意外
- 適正／適性、追及／追求／追究、成長／生長、実態／実体、機構／気候
- 収集／収拾、体制／態勢／体勢、開放／解放、既成／既製、回答／解答
- 効く／利く／聞く、図る／計る／測る／量る、勧める／薦める／進める
- 会う／合う／遭う、超える／越える、変える／代える／換える／替える
- お答え／お応え、務める／努める／勤める、断つ／絶つ／裁つ

**(b) 助詞・てにをはの誤り** ― 「の/に/を/へ/が」などの取り違え・抜け。
これも一文を意味で読まないと見えない。
- 例:「私**の**とって働くとは」→「私**に**とって働くとは」（助詞ミス）
- 例:「分かっている**の**なぜ」→「分かっている**のに**なぜ」（脱字）

**(c) 送り仮名・表記のゆれ** ― 下さい/ください、頂く/いただく、
出来る/できる など。補助動詞は仮名が原則。同一資料内での不統一も拾う。

**判断の手順:**
1. 文を**意味で読む**。「この文が言いたいこと」を先に掴む。
2. その意味に対し、使われている表記（漢字・助詞・送り仮名）が正しいかを照合する。
   例:「顧客ニーズにお答えする」→「お**応え**する」（要望に応じる意なので）。
3. **同一文書内の正しい表記を照合材料にする**。同じ語・言い回しが他のページで
   別表記になっていたら、どちらかが誤りのサイン。文脈から正しい方を判断し、
   「別ページでは○○と表記」と根拠に添える。
   （実例: あるスライドの「私のとって」は、別スライドの「私にとって」が正表記だと
   判断する決め手になった。）
4. 迷ったら**断定せず**「文脈的にはこちらでは？」と根拠（なぜそう読めるか）を添えて
   提示する。固有名詞・商品名・業界用語・造語・意図的な当て字は誤りと決めつけない。

指摘フォーマットには**種別（変換ミス／助詞／表記ゆれ 等）と、そう判断した文脈**を
必ず書く。ユーザーが「なるほど確かに」と採否を即断できるようにするため。

> 補足: Google Drive 等でライブ同期されるファイルは、抽出結果が最新版を反映する。
> チェック中に中身が変わりうるので、修正の直前に再抽出して現状を確認すると確実。

### Step 2: 重複スライド/ページの検出
```bash
python3 scripts/find_duplicates.py <file> [threshold]
```
ユニット（スライド/ページ）全体のテキスト類似度で総当たり比較し、完全一致
(`exact`)・ほぼ一致(`near`)のペアを返す。閾値は既定 0.9。docxの場合は段落単位で
繰り返しを検出する。

これはテキストベースのヒント出し。完全一致は重複の可能性が高いが、「意図的に
似たページを並べている（章扉など）」こともあるので、**断定せず候補として提示**し、
本当に消してよいかはユーザーに確認する。

### Step 3: 指摘レポートを提示
チェック結果を下記フォーマットでまとめて提示する。**この段階では修正しない。**

```
# 校正レポート: <ファイル名>

## 誤字脱字（N件）
- スライド3 タイトル: 「重要なポイト」→「重要なポイント」（脱字）
- スライド5 本文: 「ご確認下さい」→「ご確認ください」（表記ゆれ・補助動詞は仮名)

## 不適切・不自然な表現（N件）
- スライド2 本文: 「まず最初に」→「まず」または「最初に」（重言）
- スライド8 本文: 「お客様各位様」→「お客様各位」（二重敬語）

## 重複スライド/ページ（N件）
- スライド3 と スライド7 が完全一致（コピペの消し忘れの可能性）
- スライド10 と スライド11 が95%一致（要確認）

合計: 誤字脱字N件 / 表現N件 / 重複N件
```

指摘がゼロの分類は「指摘なし」と明記する。誤字の指摘には**理由**（脱字/変換ミス/
表記ゆれ等）を添えると、ユーザーが採否を判断しやすい。

### Step 4: 修正の指示を受ける
「全部直して」「誤字だけ直して」「3番と5番だけ」「重複スライドは7を消して」など、
ユーザーがどれを適用するか決める。曖昧なら確認する。重複の削除は不可逆性が高い
ので、どのスライドを残しどれを消すかを必ず明示で確認する。

### Step 5: 修正を適用
適用する編集を `edits.json` に書き出し、スクリプトで適用する。

```bash
python3 scripts/apply_fixes.py <file> edits.json
```

`edits.json` の形式:
```json
[
  {"action": "replace", "find": "重要なポイト", "replace": "重要なポイント", "unit": 3},
  {"action": "replace", "find": "お客様各位様", "replace": "お客様各位"},
  {"action": "delete_unit", "unit": 7}
]
```
- `replace`: `find`→`replace` の文字列置換。`unit`（スライド/ページ番号）を付けると
  そのページ内だけに限定。付けないと全体置換。誤変換語が他の箇所にも出てきうる
  場合は、安全のため `unit` で範囲を絞るのが基本。
- `delete_unit`: スライド/ページを丸ごと削除（重複の除去）。インデックスずれを防ぐため
  スクリプト側が後ろから処理する。複数まとめて渡してよい。

スクリプトは**修正前に元ファイルを自動でバックアップ**（`<名前>.bak-<日時><拡張子>`）
してから、元のパスに上書き保存する。適用後、件数レポート（何件置換した／何を削除した／
PDFでスキップした項目）が返るので、それをユーザーに報告する。`replaced: 0` の置換が
あれば、`find` 文字列が抽出テキストと不一致（全角半角・改行等）の可能性があるので
原因を確認する。

### Step 6: 確認
修正後、必要なら再度 `extract.py` / `find_duplicates.py` を流して、狙いどおり
直っているか・重複が解消したかを確かめてから完了報告する。

## 注意点
- **元ファイルは必ず保護**。バックアップはスクリプトが自動作成するが、念のため
  重要ファイルは事前にコピーを案内してもよい。
- 校正は提案。日本語として正しくても、その業界・その会社の慣用表現の場合がある。
  断定せず「→ こう直すのはどうか」という提示にする。
- 重複検出はテキストのみ。画像差し替えだけのページ違いは拾えない点を添える。
- 大量ページのPDFはテキスト抽出が不完全なことがある（スキャンPDF等）。抽出結果が
  空に近ければOCRが必要な可能性を伝える。
