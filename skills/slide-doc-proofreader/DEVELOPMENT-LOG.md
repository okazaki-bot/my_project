## 1. 何を作ったか

スライド・ドキュメントの校正スキル。次の3点を点検して**指摘**し、
ユーザーの**指示を受けてから**実ファイルを修正する。

1. **誤字脱字** — 漢字変換ミス（同音異義語）、助詞の誤り、送り仮名・表記ゆれ
2. **不適切・不自然な表現** — 誤用、二重敬語、冗長、文体の不統一
3. **重複スライド/ページ** — コピペ起因の「消し忘れ」「二重挿入」

対応形式: `.pptx` / `.docx` / `.pdf`

---

## 2. 最初に決めた仕様（ヒアリング結果）

実装前に3点を確認して固めた。ここが全ての前提。

| 論点 | 決定 | 補足 |
|------|------|------|
| 対象ファイル形式 | **pptx / docx / pdf** | Canva は今回スコープ外 |
| 「ページの重なり」の定義 | **重複スライド/ページ** | オブジェクトの座標重なり・はみ出しは対象外 |
| 修正の動作 | **指摘 → 指示で修正** | 自動修正はしない。元ファイルは自動バックアップ |

**「ページの重なり」の解釈が最大の分岐点だった。**
「スライドはページをコピーして使うため」という但し書きから、
(a) 重複スライドそのもの / (b) 古いテキストボックスが背面に残る座標重なり
の2解釈がありえたため、実装前に確認した。答えは (a)。
→ この決定により、検出手段が「テキスト類似度の総当たり比較」に確定した。
（(b) だったら図形座標の矩形交差判定が必要で、まったく別の実装になっていた）

## 3. 設計方針 ― 最重要の判断

### スクリプトとモデルの役割分担
このスキルの肝は**「何をコードにやらせ、何をモデルに判断させるか」の線引き**。

| 担当 | 作業 | 理由 |
|------|------|------|
| **スクリプト** | テキスト抽出・重複検出・修正適用 | 決定的・再現性が要る。取りこぼし/座標ズレは許されない |
| **モデル** | 誤字脱字・表現の判断 | 意味を読む作業。ルール化不能で、文脈依存 |

誤字判定をコード（辞書・正規表現）でやろうとすると、同音異義語の誤変換は
**原理的に捕まらない**（単語単体では正しい漢字のため）。逆に抽出や
バックアップをモデルの手作業に任せると事故る。だからこの分担にしている。
**この線引きを崩す改修はしないこと。**

### 位置情報を必ず持たせる
`extract.py` はテキストを「スライド番号・ブロック種別（title/body/table/notes）」
つきで返す。指摘が「スライド3のタイトル」と特定できないと、
ユーザーが直す箇所を選べず、Step 4（指示を受ける）が成立しないため。

### PDF はチェック専用
PDF のテキスト書き換えは安全に行えない（フォント埋め込み・字形配置の都合）。
そのため PDF は**指摘のみ**、修正は元データ（pptx/docx）側で行う前提とした。
ただし**重複ページの削除だけは可能**なので `delete_unit` は対応している。

## 4. 構成

```
slide-doc-proofreader/
├── SKILL.md              … 手順（Step 0〜6）と校正の観点
├── DEVELOPMENT-LOG.md    … この文書
└── scripts/
    ├── extract.py        … pptx/docx/pdf → 位置情報つきJSON
    ├── find_duplicates.py… 重複スライド/ページを類似度で検出
    └── apply_fixes.py     … 置換・ユニット削除を適用（自動バックアップ）
```

### 依存ライブラリ
```bash
pip install python-pptx python-docx pypdf
```
環境メモ: `/usr/bin/python3`（Python 3.9.6）に導入済み。pypdf は元から存在。

### 各スクリプトの要点
- **extract.py** — 形式ごとに分岐。pptx はテキスト枠・表・ノートを拾う。
  docx はページ概念が無いため全体を1ユニットとし段落を blocks にする。
- **find_duplicates.py** — 空白除去で正規化 → 総当たり比較（`difflib`）。
  閾値既定 0.9。完全一致=`exact` / ほぼ一致=`near`。
  docx のみ段落単位で繰り返しを検出。
- **apply_fixes.py** — `edits.json` を受けて適用。**必ず先にバックアップ**
  （`<名前>.bak-<日時><拡張子>`）してから元パスに上書き（リンク・参照を壊さないため）。
  - `replace`: `unit` 指定でスライド単位に絞れる（誤爆防止）
  - `delete_unit`: 削除はインデックスずれ防止のため**後ろから処理**
  - run の書式を保つため「段落の先頭 run にまとめ、残りを空にする」方式を採用

## 6. 運用しながらの改善履歴

**実際に使って出た問題をその都度スキルに還元した。この3件が現在の挙動の理由。**

### 改善① 対象はユーザーが指定する（勝手に探さない）
- **きっかけ**: 「誤字脱字チェックして」に対し、Claude がプロジェクト内を
  勝手に検索して候補PDFで進めようとした。ユーザーから
  「ファイルやフォルダをこちらで指定させてください」と差し戻し。
- **対応**: Step 0 を書き換え。**パスが示されなければ必ず尋ねる**、
  推測で進めないと明記。あわせて**フォルダ指定**にも対応
  （中の pptx/docx/pdf を列挙 → 件数と内訳を見せて対象を確認 → 1つずつ処理）。
- **why**: 対象の取り違えは、その後の作業が全部無駄になる。確認コストの方が安い。

### 改善② 漢字の変換ミスを文脈で読む
- **きっかけ**: ユーザーから「漢字の変換ミスも前後の文脈を読み取って
  チェックするようにしてください」。
- **対応**: SKILL.md に「校正の観点」節を新設。同音異義語の例を列挙し、
  「意味で読む → 表記を照合 → 迷ったら断定せず根拠つきで提示」の手順を明記。

### 改善③ 観点を(a)漢字変換 (b)助詞 (c)表記ゆれ に拡張＋文書内照合
- **きっかけ**: ②の観点で再チェックしたところ、実際にヒットしたのは
  漢字変換ミスではなく**助詞の誤り**（「私**の**とって」→「私**に**とって」）だった。
  しかも判断の決め手は、**同じ資料の別スライドに正しい表記があったこと**。
- **対応**: 観点を3種類に整理し、
  **「同一文書内の正しい表記を照合材料にする」**テクニックを手順に明文化。
  ライブ同期ファイル（Google Drive等）は修正直前に再抽出する注意も追記。
- **why**: 「同じ語が別ページで違う表記＝どちらかが誤りのサイン」は、
  辞書では絶対に出せない、文書単位で読むからこそ効く判定。ここが再現性の要。

## 7. 実地適用の実績（GM合宿資料 Vol1〜4）

改善①②③はすべてこの実地適用から出た。参考として結果を残す。

対象: `共有ドライブ/…/20260708,09,10_GM合宿/資料　原文/`（Vol1・2・4=pptx、Vol3=pdf）

**修正を適用した分:**
| ファイル | 内容 | 件数 |
|---------|------|------|
| Vol2 | 「のよう**は**」→「のよう**な**」（スライド6・7・8） | 3 |
| Vol4 | 「分かっているの」→「分かっているの**に**」（スライド17） | 1 |

バックアップ: 同フォルダに `*.bak-*.pptx` として自動生成済み。

**指摘したが未対応の分:**
- Vol1 スライド2「私**の**とって」→「私**に**とって」（ユーザー判断で今回見送り）
- Vol1 スライド4 に `file:///Users/.../jupiter_saturn_orbit_from_1800.html` の残骸
- Vol2 スライド17・Vol4 スライド11 に「11 / 12 / 12」の数字残り（コピー残しの疑い）
- Vol4 スライド20・21 が同一タイトルで重複
- Vol3.pdf: `All Right Reserved` → `All Rights Reserved`、「物質的**欲望**」の表記不統一
  （PDFのため元データ側での修正が必要）

**学び**: Vol4 のタイトルが「Vol.2」のままだった（Vol2 をコピーして番号を直し忘れ）
という、まさにこのスキルが狙った事故を実際に検出できた。
なお対象が Google Drive 同期下にあり、作業中に別途修正が入って
中身が変わることがあった（→ 改善③の注意書きの由来）。

## 8. 既知の制約

- **重複検出はテキストのみ** — 画像だけ差し替えたページの違いは拾えない。
  最終判断は人が行う前提のヒント出しに徹している。
- **PDFは修正不可**（重複ページ削除を除く）。
- **PDFのテキスト抽出は不完全なことがある** — 字間にスペースが入る等
  （Vol3.pdf で発生）。文字レベルの誤字判定は精度が落ちる。スキャンPDFはOCRが必要。
- **意図的に似たページ**（章扉など）も重複候補に挙がる → 断定せず確認する設計。
- 造語・業界用語・固有名詞は誤り扱いしない（GM合宿の「正面来果」「上極来果」「予悔」等）。
