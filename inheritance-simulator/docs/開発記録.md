## 4. 主要な意思決定の記録

| 決定 | 理由 |
|---|---|
| 参考元サイトのコード/デザインは複製しない | 著作権への配慮。機能フローと計算項目のみ再現 |
| 完全クライアントサイド（localStorage） | ダブルクリックで動く手軽さ優先。相続情報がサーバーに残らない＝公開時のプライバシー説明にも使用 |
| 付表の数値は国税庁サイトから取得して収録 | 「プロ以上の正確さ」要件。記憶に頼らず一次ソースで検証 |
| 宅地造成費の単価はデフォルト値を持たせない | 都道府県・年度で異なるため、不正確な既定値より転記方式＋ガイドが安全 |
| CSV取込は実装しない | ユーザー指示による除外 |
| 公開は認証なし（Basic認証なし） | ユーザー判断（2026-07-10）。データがブラウザ内のみである点を確認済み |
| 仕様書はアプリ内埋め込みで公開 | file://でもfetch不可のため `js/spec-doc.js` 埋め込み方式 |

## 5. 運用手順メモ

**デプロイ更新**（Claude拡張はXserver管理画面をブロックするため、アップロードは常にユーザーの手動操作）:
1. ローカルで修正 → プレビューで検証
2. 変更ファイルだけを Xserver ファイルマネージャで上書きアップロード（場所: `lifeplanadvisor.or.jp/public_html/souzoku.lifeplanadvisor.or.jp/`）
3. 全ファイル更新時は `souzoku-deploy.zip` を作り直してアップロード→展開（**展開はzip名のサブフォルダに入るので、中身をdocrootへ移動する**こと）

**仕様書MDを更新したら**（アプリ内表示への反映）:
```bash
cd ~/Documents/my_project/inheritance-simulator
python3 -c "import json; md=open('docs/計算ロジック仕様書.md',encoding='utf-8').read(); open('js/spec-doc.js','w',encoding='utf-8').write('\"use strict\";\nconst SPEC_MD='+json.dumps(md,ensure_ascii=False)+';\n')"
```
その後 `js/spec-doc.js` をサーバーへ上書きアップロード。

**検証の定石**: `npx serve` でプレビュー → `preview_eval` でエンジン関数を直接呼ぶテスト（過去の全テストは計算例つきで会話内実施済み。代表例は仕様書§9）。
